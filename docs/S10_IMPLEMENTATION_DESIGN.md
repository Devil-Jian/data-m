## Initial S10 API
`provenance_trace({request:{projectId,action,id,offset?,limit?}})` supports action `panel`, `asset`, `version`. It is read-only, checks the active project, uses a recognized controlled SQLite repository, and returns exact version joins, SHA, bytes, paper/figure/panel use, analysis ID/input-vs-result role/freeze timestamp, persisted included replicate IDs, and record count with pagination. 1–200 rows per page. Panel edges and analysis edges are **distinct**; a Panel sharing a version with an Analysis does not establish an explicit Panel→Analysis binding. Soft-deleted asset links remain valid historical scope evidence. A future response version should additionally report each link's current/deleted state and representative source details. No schema v4 currently required for exact-version references.

## Design for remaining Figure export (NOT IMPLEMENTED)
Authoritative manifest v1 must include Figure/Panel order, logical use edges, exact version IDs, asset IDs, blob SHA/size, analysis relation evidence and historical inclusion, source metadata, audit references, and per-file SHA result. Output ordering shall be deterministic; shared versions may share exported bytes while retaining all logical references. No fuzzy matching. No source mutation or lossy transform. Native UI must authorize a target directory; the Rust exporter must reject traversal, symlinks/reparse escapes, device names, pre-existing conflicting targets, TOCTOU risks, missing/corrupt blobs. Stage in a sibling temporary directory on the same filesystem, rehash every CAS byte stream, then publish only after complete verification, never overwrite. Failure/cancellation must leave zero successful partial published package and leave source CAS/SQLite untouched.

## Implemented partial Figure export core and candidate fix (unverified)
The Figure export core queries exact `panel_asset_versions` and immutable CAS digest and file size, stages per SHA under an existing absolute destination, writes `figure-manifest.json`, and publishes only on full verification. Source names are preserved as JSON metadata; SHA-only physical filenames avoid Windows reserved names and collisions. Exact matching Analysis version references and their historical included Replicate IDs are emitted as associated references, **not** proof of a causal Panel→Analysis relationship. Native directory picker authorization, Windows handle-based TOCTOU defense, cancel/request-id tracking, UI confirmation and progress are still outstanding, so core is not exposed via user IPC.

## Native Windows export IPC (new candidate, requires CI + security validation)
The native Rust `figure_export` command uses `action=preview|export`, project/paper/figure identifiers, a distinct export `requestId`, and `confirm=true` for writes. No frontend-supplied disk path is accepted. Windows Shell folder selection runs on a dedicated COM STA thread, then the S3 import filesystem's vetted directory-handle guard pins target ancestry and the CAS object directory. Export stages a unique directory on the target filesystem, hashes each original CAS file twice, writes a JSON Figure Manifest, checks cancellation, validates target handles, then publishes a new, non-overwriting directory. `figure_export_cancel` sets a registered cancellation flag, checked while streaming. The Tauri event `s10-figure-export-progress` reports physical verified file counts.

**Unresolved security and acceptance:** Native Windows picker COM behavior and handle checks require CI/Windows device validation; the request-id registry currently prevents *concurrent* duplicates but lacks durable restart-safe idempotency. Interrupted-process orphan staging and exact atomic publish race on every filesystem require further adversarial testing. Manifest audit and representative-source history is still incomplete. These gaps prohibit `machine_passed` or `accepted` status.
