# S1 Project Tree Implementation Plan

**Goal:** 持久化 Project → Theme → Assay CRUD，UI 提交后从 Rust/SQLite 重查，不使用演示数据表示成功。
**Spec:** AI_DEV_EXECUTION_SPEC.md S1；DATA_M_AI_TASKS.json S1。S0 已人工签收并合并，起点 main `8a7d2f9`。
**Architecture:** Rust project_tree 模块维护受控、独立的 S1 测试数据库。单个结构化 IPC `project_tree` 接收操作；React 仅显示返回快照，不执行 SQL。
**Tech Stack:** React/TypeScript、Tauri、rusqlite，沿用锁文件。

## Global Constraints

仅 Project/Theme/Assay；不开放 Group、Replicate、CAS 或文件写入接口。不迁移或初始化未知既有 DB。不自动合并 S1 或宣布人工验收通过。

## Interfaces

- IPC `project_tree({request})`。
- Request camelCase: `{action: 'list'|'create'|'rename'|'delete', kind?: 'project'|'theme'|'assay', id?: string, parentId?: string, name?: string, requestId?: string}`。
- Response: `{nodes: Array<{id:string,kind:'project'|'theme'|'assay',parentId:string|null,name:string}>}`，只含未软删除节点。
- Rejection `{code:string,message:string}`。Mutation requestId 必须有值；相同 ID/载荷幂等，ID 被不同载荷重用报错。
- Rust 分配稳定 ID；父级必须存在且未删除；禁止删除有下级或资产关联的节点。所有变更和请求记录同事务，响应重查 DB。
- 浏览器使用明确标记的 Mock API；原生使用真实 IPC，不允许浏览器 mock 冒充 Native 成功。

## Review Focus

未知 DB 原样拒绝；跨父级/删除父级/重复请求失败无部分提交；重启持久化；错误不暴露本机路径；空态与异步重试不回退为 Demo 成功。
