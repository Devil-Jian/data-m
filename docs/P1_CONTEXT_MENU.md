# P1 Explorer 右键菜单与快捷键作用域（Issue #7）

> 当前功能是基于演示 Asset ID 的**无写入交互层**。不包含任何可执行的真实文件移动、复制、删除或重命名。

## 交互规范

1. 在已选中的文件上右键：保留全部选中的 Asset ID；右键焦点仅指向当前文件。
2. 在未选中的文件上右键：仅选中该文件，不附带此前的选择。
3. 右键空白工作区：显示当前演示剪贴板的粘贴操作（如有）；没有内容时提示无可用资产。
4. 文件右键菜单包含复制、剪切、重命名、删除；多选时重命名不可操作。
5. 右键菜单支持键盘 Tab 切换和 Esc 退出；Esc 只关闭菜单，不清除已选文件。
6. 点击工作区外部或滚动时关闭菜单，避免菜单悬浮在旧坐标。
7. Ctrl+A/C/X/V、Delete、F2 和方向导航只在当前 Explorer 工作区拥有焦点时处理；搜索输入框、论文管理等区域不得触发文件快捷键。
8. 操作意图通过现有 `onCopy`、`onCut`、`onPaste`、`onDelete`、`onRename` 回调传递；提示应明确**没有执行真实文件操作**。

## 自动化测试

`npm run test:interaction` 覆盖多选右键保留、非选中项替换、过期 Asset ID 拒绝。

`npm run test:e2e` 覆盖已选双文件右键菜单复制、未选文件右键单选、空白区域模拟粘贴、Esc 关闭菜单及输入框 Ctrl+A/Delete 隔离。Windows Chromium 与 Linux Chromium 都运行相同 Playwright 用例。

## 已知限制

- 演示剪贴板是当前 React Hook 的内存数据，不与 Windows 系统剪贴板共享。
- 删除、重命名、复制、粘贴均不会改变任何真实文件或 SQLite 数据。
- 右键菜单目前为自绘基础组件，复杂的 WAI-ARIA 菜单方向键循环、文件冲突对话框、撤销栈仍未实现。
- 真实菜单操作必须等 #14 / #6 的 Rust/SQLite/CAS 安全事务与不可变引用模型完成后才能启用。
- Windows WebView2 鼠标交互和 DPI 100/125/150% 的真人验收尚未签署。

## Windows 原生验收

- [ ] 拖入测试文件至 Windows Tauri 预览，确认不会修改真实文件。
- [ ] Ctrl+单击两个文件，再在其中一个上右键，应显示“已选择 2 个文件资产”。
- [ ] 右键第三个未选文件，应仅选中第三个。
- [ ] 点击复制/剪切/删除应只显示演示提示，无外部文件变化。
- [ ] 在搜索框按 Ctrl+A/Delete 不影响选区，不触发删除事件。
- [ ] 在工作区右键菜单按 Esc 后，已选文件仍被选中。
- [ ] 高 DPI、窗口缩放和虚拟列表滚动时菜单位置正确。

只有通过真实 Windows 交互与完整后端安全验收，才可认为 Issue #7 正式完成。
